# RVC SW Controller Functional and Non-Functional Requirements

## 1. Purpose

이 문서는 Robot Vacuum Cleaner(RVC) SW Controller의 요구사항을 기능 요구사항과 비기능 요구사항으로 구분해 정리한다.

현재 범위는 전원이 켜진 동안 자동 청소 상태를 유지하는 RVC의 주행 방향, 센서 판단 우선순위, 먼지/장애물 대응 회전, 청소 출력 모드 제어이다. 센서, 모터, 청소 장치 등 하드웨어 제어의 상세 설계와 구현은 제외하고, 소프트웨어 컨트롤러의 판단과 동작 흐름에 집중한다.

## 2. Functional Requirements

| ID | Requirement | Description |
| --- | --- | --- |
| FR-001 | 자동 청소 수행 | RVC는 가정용 바닥 표면을 자동으로 청소해야 한다. |
| FR-002 | 전원 ON 중 청소 상태 유지 | RVC는 전원이 켜져 있으면 항상 청소 상태를 유지해야 한다. |
| FR-003 | 기본 일반 모드 | RVC는 먼지 감지 대응 중이 아닌 모든 경우 일반 모드로 청소해야 한다. |
| FR-004 | 후방 장애물 센서 사용 | RVC는 후방 장애물 센서 입력을 처리할 수 있어야 한다. |
| FR-005 | 진행 방향 상태 유지 | RVC는 현재 진행 방향을 전진 또는 후진 상태로 유지해야 한다. |
| FR-006 | 센서 판단 우선순위 | RVC는 매 판단 주기마다 먼지 감지를 먼저 확인하고, 먼지가 감지되지 않은 경우에만 현재 진행 방향의 장애물을 확인해야 한다. |
| FR-007 | 먼지 감지 우선 처리 | 먼지와 장애물이 동시에 감지되면 RVC는 먼지 감지 대응 절차를 수행해야 한다. |
| FR-008 | 전진 중 먼지 감지 최초 회전 | 전진 중 먼지가 감지되면 RVC는 Boost 모드로 전환하고 최초 시계 방향 90도 회전을 1회 수행해야 한다. |
| FR-009 | 전진 중 먼지 감지 후 후방 센서 확인 | 전진 중 먼지 감지 후 RVC는 후방 센서에서 장애물이 감지되지 않을 때까지 시계 방향으로 90도씩 추가 회전하며 센서를 확인해야 한다. |
| FR-010 | 전진 중 먼지 감지 후 후진 전환 | 후방 센서가 장애물을 감지하지 않으면 RVC는 Boost 모드를 종료하고 진행 방향을 후진으로 Toggle해야 한다. |
| FR-011 | 후진 중 먼지 감지 최초 회전 | 후진 중 먼지가 감지되면 RVC는 Boost 모드로 전환하고 최초 반시계 방향 90도 회전을 1회 수행해야 한다. |
| FR-012 | 후진 중 먼지 감지 후 전방 센서 확인 | 후진 중 먼지 감지 후 RVC는 전방 센서에서 장애물이 감지되지 않을 때까지 반시계 방향으로 90도씩 추가 회전하며 센서를 확인해야 한다. |
| FR-013 | 후진 중 먼지 감지 후 전진 전환 | 전방 센서가 장애물을 감지하지 않으면 RVC는 Boost 모드를 종료하고 진행 방향을 전진으로 Toggle해야 한다. |
| FR-014 | 전진 중 장애물 감지 최초 회전 | 전진 중 먼지가 감지되지 않고 전방 장애물이 감지되면 RVC는 일반 모드를 유지한 채 최초 시계 방향 90도 회전을 1회 수행해야 한다. |
| FR-015 | 전진 중 장애물 감지 후 후방 센서 확인 | 전진 중 장애물 감지 후 RVC는 후방 센서에서 장애물이 감지되지 않을 때까지 시계 방향으로 90도씩 추가 회전하며 센서를 확인해야 한다. |
| FR-016 | 전진 중 장애물 감지 후 후진 전환 | 후방 센서가 장애물을 감지하지 않으면 RVC는 진행 방향을 후진으로 Toggle해야 한다. |
| FR-017 | 후진 중 장애물 감지 최초 회전 | 후진 중 먼지가 감지되지 않고 후방 장애물이 감지되면 RVC는 일반 모드를 유지한 채 최초 반시계 방향 90도 회전을 1회 수행해야 한다. |
| FR-018 | 후진 중 장애물 감지 후 전방 센서 확인 | 후진 중 장애물 감지 후 RVC는 전방 센서에서 장애물이 감지되지 않을 때까지 반시계 방향으로 90도씩 추가 회전하며 센서를 확인해야 한다. |
| FR-019 | 후진 중 장애물 감지 후 전진 전환 | 전방 센서가 장애물을 감지하지 않으면 RVC는 진행 방향을 전진으로 Toggle해야 한다. |
| FR-020 | 90도 단위 센서 재확인 | 먼지 또는 장애물 대응 절차에서 RVC는 매 90도 회전 후 대상 센서를 재확인해야 한다. |
| FR-021 | Boost 모드 적용 범위 | Boost 모드는 먼지 감지로 시작된 제자리 회전 중에만 적용해야 한다. |
| FR-022 | 정상 주행 유지 | 먼지와 현재 진행 방향의 장애물이 모두 감지되지 않으면 RVC는 현재 진행 방향으로 일반 모드 청소를 계속해야 한다. |
| FR-023 | 시뮬레이터 명령 인터페이스 | `rvc_app`은 시뮬레이터와 시스템 테스트 클라이언트가 센서 입력, 초기화, 종료 명령을 전달할 수 있도록 line-based TCP 명령을 처리해야 한다. |
| FR-024 | 컨트롤러 상태 조회 | `rvc_app`은 시뮬레이터와 시스템 테스트 클라이언트가 현재 이동 상태, 센서 상태, 진행 방향, 최근 주행 명령, 청소 출력 모드를 조회할 수 있어야 한다. |

## 3. Non-Functional Requirements

| ID | Requirement | Description |
| --- | --- | --- |
| NFR-001 | 하드웨어 독립성 | 자동 청소 로직은 센서, 모터, 청소 장치의 상세 하드웨어 구현과 분리되어야 한다. |
| NFR-002 | 센서 확장성 | 전방/후방 장애물 센서와 먼지 센서 입력 처리는 추가 센서 확장을 고려해 분리되어야 한다. |
| NFR-003 | 동작 정책 변경 용이성 | 먼지 우선순위, 회전 방향, 회전 단위, 진행 방향 Toggle 정책은 변경하기 쉬워야 한다. |
| NFR-004 | 유지보수성 | 자동 청소 로직은 이해하기 쉽고 수정 범위가 제한되도록 구성되어야 한다. |
| NFR-005 | 기능 확장성 | 특정 지점 선회 청소, 모바일 앱 통신, 머신러닝 기반 청소 판단 기능을 추후 추가할 수 있어야 한다. |
| NFR-006 | 설정 가능성 | 회전 단위, 회전 방향 정책, Boost 출력 수준, 예외 처리 정책 등은 추후 조정 가능해야 한다. |
| NFR-007 | 관심사 분리 | 센서 입력 해석, 먼지/장애물 우선순위 판단, 진행 방향 상태 관리, 이동 명령 생성은 서로 분리된 책임으로 다뤄져야 한다. |
| NFR-008 | 시뮬레이션 경계 분리 | Python 시뮬레이터의 지도, 렌더링, 물리 적용, coverage assist는 C++ 자동 청소 판단과 분리되어야 한다. |
| NFR-009 | 상태 명확성 | 현재 진행 방향, 청소 출력 모드, 회전 절차 진행 여부는 명확한 상태로 표현되어야 한다. |
| NFR-010 | 테스트 가능성 | 먼지 우선 처리, 장애물 처리, 90도 반복 회전, 전진/후진 Toggle은 단위 테스트와 시스템 테스트로 검증 가능해야 한다. |

## 4. Future Extension Candidates

다음 항목은 현재 필수 구현 범위는 아니지만 설계 시 확장 가능성을 고려한다.

- 센서 추가 또는 센서 종류 변경
- 특정 지점 선회 청소
- 모바일 앱과의 통신
- 머신러닝 및 추론 기반 청소 효율 개선
- 회전 반복 실패 시 최대 회전 횟수, 정지, 사용자 알림 등 예외 정책

## 5. Out of Scope

- 센서 하드웨어의 상세 설계 및 구현
- 모터, 브러시 등 하드웨어 제어의 상세 구현
- 시뮬레이터의 물리 정확도 또는 실제 주행 동역학 모델링
- 모바일 앱 자체 구현
- 머신러닝 모델의 학습 및 상세 구현
- 회전 반복이 계속 실패하는 경우의 최대 회전 횟수 또는 오류 정책
